# diaithir-worldgen-structures
Data-only NeoForge 26.1.2 module. Clean-room: 197 original (186 + 5 Ascendant rite sites via tools/gen_rite_sites.py) structures designed from public behaviour descriptions of 40 all-rights-reserved or unknown-licence structure mods; no source code, templates or assets used.
- `tools/gen.py` turns `blueprints/*.json` (block-grid designs) plus `tools/specs.json` into `src/main/resources` (templates, jigsaw structures, structure sets, loot tables).
- Integration (INTEGRATION.md): biome tags use vanilla/`c:` tags, per-Age structure tags (`age_i`..), `diaithir_events.json` (calendar year, disaster, war, raid; ruin states), Codex entries and a quest per structure, `migration.json` maps old mod prefixes to new ids.
- TODO: upgrade rules (no working blocks here), cross-mod recipes (none), stronger biome tag coverage, client world-join and locate test.
- Build jar: `cd src/main/resources && zip -r ../../../diaithir-worldgen-structures-1.0.0.jar .`

## Panscriptum sites (tools/lib_sites.py)
All 44,015 STRUCTURE entries of the Panscriptum (library-content/content.sqlite, text from codex-store/library.sqlite) are generated as data: one plaque template per entry (a lectern holding a written book with the entry's own summary verbatim, author "Panscriptum"), 12 site classes picked by keywords in the entry text, shared class buildings per soil and size, 3,749 jigsaw structures (planet x class x Age band), one structure set per planet, biome tag `diaithir_worldgen:lib/<planet>` and Age tags `lib_age_N` (planet opens_age + band). `library_sites.tsv` maps entry id to planet, class, band and template. Regenerate: `python3 -I tools/lib_sites.py` (about 25 s).
- Terra (`diaithir`) uses `#minecraft:is_overworld`. Every other planet's tag points at the optional biome tag `#diaithir_planets:<planet>`, which the biomes-dims module must fill with that planet's own biomes; a structure set cannot be limited to a dimension any other way, so planets without their own biomes get no sites yet.
- Checked: vanilla 26.1.2 server loads the pack with no errors, `/locate` finds Terra sites of all 12 classes, templates load and the lectern book reads back. Not checked: planet dimensions in game, Ember/Hollow/Quiet heights, NeoForge full-pack boot.
- `pack.mcmeta` here uses `pack_format` only; a plain datapack folder on 26.1 needs `min_format`/`max_format` (101).
- Terra (407 entries): every entry has its own building (`structure/lib/diaithir/b/`), shaped from its text (pyramid, stone ring, mound, cave, dome, gate, walled town, towers, harbour, bridge, rows of figures; otherwise the class building) and made of the materials the text names (brick, clay, timber, sand, copper, glass and steel...). Size from words like huge/small. Chests use `lib/loot/<class>` tables; tomb, delve, fortress and ruin sites carry a vanilla mob spawner as a placeholder until the mobs lane's entities exist. NPC hooks are not placed yet.
- NPC hook: where an NPC of the same planet is named in a site's text (3,894 sites), the plaque has a barrel beside the lectern with CustomName `lib_npc:<call number>:<count>`; `library_sites_npc.tsv` lists the same pairs. The NPC lane turns the barrel into that person on first load.
- Checked with the planet biome tags of diaithir-ports #145 loaded: `/locate` finds Ashestith sites inside `diaithir_planets:ashestith` and none in the overworld.
- Mob spawners name body-plan entities of diaithir-fauna (`diaithirfauna:<plan>`, PR #154): tomb scorpion, delve giant_arthropod, fortress theropod, ruin lizard, harbor crocodilian. In a planet dimension the fauna mod picks a hostile Library creature of that plan; elsewhere it uses the plan's normal species. Not tested in a live world.
- Checked on NeoForge 26.1.2.116 with diaithir-fauna (#154) loaded: no registry errors; placed delve and tomb templates carry spawners that name `diaithirfauna:giant_arthropod` and `diaithirfauna:scorpion`; all five body-plan ids summon. A spawner firing needs a player nearby, so the spawn itself is untested (no player in a headless cloud server).
- Spawner fire test (NeoForge 26.1.2 + diaithir-fauna #154, headless fake player S6843 standing near the placed site): the tomb spawner produced a `diaithirfauna:scorpion` and the delve spawner six `diaithirfauna:giant_arthropod`, in the overworld (plan's normal species). Planet dimensions not covered: #145 now creates dimensions at runtime, which needs the biomes mod loaded.
- Planet dimension check with diaithir-overworld-biomes (#145) loaded and `/planet load alaima`: `/locate` finds Alaima delve sites inside `diaithir_planets:alaima`. A spawner fire test there was not possible: with that mod installed NeoForge refuses the vanilla-protocol fake player (S6843); it needs a NeoForge-negotiating bot or the PC.
- Settlements: all 19,081 SETTLEMENT entries are sites too (class `settlement`: a ring or grid of houses with a well, 2 to 4 per side by size; Terra's 128 are built per entry from the materials in their text). Their plaque carries a barrel named `lib_settle:<settlement id>:<n>` (n = 2 + tier, max 6) that the NPC lane turns into that settlement's people. They use a separate structure set per planet (`lib/<planet>_settle`, wider spacing). Placement by the biome named in the planets lane's `settlements/<planet>.tsv` is not used yet; sites key on the planet tag only.
- Settlement style and biome (all planets): `settle_style()` reads each settlement's own text for materials (stone, brick, clay, timber, coral, crystal, bone, ash, glass, sand and so on), size words, walls/gate, hall or palace, and water/harbour, and picks one of 412 shared building styles (`structure/lib/bld/style/`). Each settlement is keyed to its biome with the planets lane's `settlements/<planet>.tsv`: `tools/planet_biomes.py` (S6848) maps the biome_entry to the planet's biome id (`tools/planet_biome_map.json`, from #145), and each (planet, biome, Age band) is its own structure whose biome tag is `lib/<planet>/b/<biome>`. All 18,953 planet settlements map; Terra's 128 use the overworld tag. Checked on NeoForge with #145 loaded: `/locate` finds `lib/alaima/settlement_0_elaerwen` in Alaima (about 50,000 blocks out, since the planet uses large biomes).
- Settlement density: besides the biome-keyed sets (one per planet and biome, spacing 24 chunks), each planet has a generic set `lib/<planet>_settle_any` (spacing 20 chunks) whose structures accept any land biome of the planet (`lib/<planet>/b/land`). `/locate` from spawn: Grimukougok 314 blocks, Ashestith 1,549 blocks, Alaima 3,857 blocks (Alaima's nearest land biome is itself 2,151 blocks away, so that is the planet's terrain, not the spacing).
- Recurrent Complex function group (`tools/rc_gen.py`, S6850), clean-room from the mod's public description: **mazes** (five themes stone, sand, nether, ice, deep; jigsaw labyrinths of 7x6x7 cells with hub, room, cross, tee, turn, straight and dead-end pieces, chests and spawners in rooms, dead-end caps), **transformers** (processor lists `rc/desert`, `rc/snow`, `rc/jungle`, `rc/nether`, `rc/mossy` that swap a structure's materials for the biome), **inventory generators** (loot tables `rc/chest/armory|library|treasury|kitchen|tomb|lab`), and natural generation with biome tags (`#c:is_desert`, `#c:is_snowy`, `#c:is_underground`, vanilla overworld/nether tags) and Age tags `rc_age_<n>`. Recurrent Complex keeps structures as config files, not registry ids, so `migration_recurrentcomplex.json` only records the prefix and the fallback maze structures. Checked on NeoForge 26.1.2: pack boots, `/locate` finds the stone maze, `/place` builds a multi-cell maze with chests and spawners. Not checked: the other four themes in world, maze connectivity by eye, c: tag coverage on the full pack.
- Habitat on planets: non-settlement sites are keyed by class to the planet's own biome kinds instead of the whole planet tag: harbours to shore, delves to caves (hollows, grottoes), bridges to river, everything else to land biomes (tags `lib/<planet>/b/coast|cave|river|land`; Terra uses beach/ocean, lush/dripstone caves, river, overworld). Checked on Ashestith with #145: harbour 3,391 blocks, delve 452, bridge 339, tower 3,242 from spawn.

## Age VII/VIII sites and c: tags (11-03)
- `tools/asc_gen.py`: 12 game-original sites from plans/ASCENDANT.md (nine Ascendant rite sites for Ages VII/VIII, three shard sites for VIII), vanilla blocks only, structures `asc/<id>`, tags `asc_age_7` and `asc_age_8`. They are not Panscriptum entries. All placed on a headless vanilla server with `/place`.
- `tools/c_tags.py`: `c:` structure tags (`c:villages`, `c:ruins`, `c:dungeons`, `c:mazes`, `c:diaithir_worldgen/<class>`) and biome tag `c:has_diaithir_worldgen_structures`.
- The 9 excavation-site STRUCTURE rows from library-to-content (`<event id>.site`) are built by lib_sites.py from their event text.
